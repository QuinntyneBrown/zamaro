Button

Buttons let a booker act: show the lineup, request a booking, try again. One yellow button per view says what matters most.

WCAG 2.2 AAStatus: stableNative <button>Class .btn

Overview

Use a button when activating it changes something: it submits the booking request, retries a failed load, saves an artist or opens a menu. Use a link when it only goes somewhere. Use the round save toggle on tickets, where space is tight.

  • Primary (yellow fill, ink outline) is the one action the view exists for: “Show the lineup”, “Request to book”. Never two in the same view.
  • Secondary (the default look: paper with a charcoal rule) is for every other action.
  • Ink (solid charcoal) is a strong secondary that sits beside yellow without competing, such as “See Abigail’s profile” on the headliner.
  • Ghost has no frame. Use it in dense places such as the top bar and toolbars.
  • Link looks like a link but acts like a button. Use it for minor actions inside a sentence.
  • Danger is for destructive actions (cancel a booking, remove an artist) and only appears inside a confirmation dialog.

Anatomy

  1. LabelBold sans, 14px, uppercase, 0.08em tracking. It is the accessible name.
  2. Icon (optional)20px, square-capped 2.25 stroke, currentColor, aria-hidden. A trailing arrow means “go on”.
  3. ContainerHeight from --control-height-*, square corners, 2px rule, 20px side padding.
  4. Print shadow (hover)A hard 4px offset in --color-shadow while the button lifts 4px up and to the left: ink on newsprint, yellow on stage.

Variants

Variants change emphasis, not meaning. Choose by how much attention the action deserves in this view.

Primary, secondary, ink, ghost, link, danger: emphasis from highest to lowest. Danger is only for destructive confirmations.

Sizes

Medium is the default and already meets the 44px comfortable target. Use large for the action a whole surface exists for: the booking bar submit, the booking stub, the band. Use small inside list rows, such as “Pick” on tour dates.

Heights --control-height-sm/md/lg; side padding --space-3/5/6; label --font-size-xs/sm/md.

States

Every variant has the same states. Hover, focus and active are forced here with data-state so you can review them without a mouse. Real pages get them from :hover, :focus-visible, :active, :disabled and aria-busy.

Both themes

  • Hover lifts the button 4px up and to the left over a hard print shadow, like a misregistered screen print. Ghost and link buttons highlight instead of lifting.
  • Active presses the button back flat. The shadow disappears, which reads as “pressed into the paper”.
  • Loading sets aria-busy="true", adds a spinner after the label and ignores further clicks. The label may change to a present-tense verb (“Checking calendars…”), but the button never gets narrower.
  • Disabled uses the native attribute. It is not focusable and turns grey on a sunken fill, so a disabled primary is no longer yellow. Prefer leaving the button enabled and explaining what is missing when it is pressed.

Responsive behaviour

  • Labels never truncate. As a safety net they wrap to a balanced second line rather than overflow, but a label that wraps at 360px is too long, so shorten it. “Request to book · Sat 14 Nov” is the longest that still fits on one line inside the booking stub at 360px. The mocks’ “Search within 120 km · 2 choirs free” wraps and should become “Search within 120 km”, with the count moved into the sentence above.
  • Below --layout-breakpoint-sm (640px), a form’s submit button fills its container (.btn--block), as in the booking bar and stub.
  • Button rows use .cluster and wrap onto a new line. In alerts and dialogs the primary action comes first in the DOM and on the left. On phones, dialog footer buttons stretch to equal widths.
  • Touch: every size is at least 36px tall. Small buttons are only used inside list rows that have 16px of vertical padding, so their effective target is 44px or more.

Theming

The button reads semantic tokens only, through component tokens that each variant and context overrides: --btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-fg-hover, --btn-bg-active, --btn-shadow-hover, --btn-transform-hover, --btn-height, --btn-padding, --btn-font-size. A theme changes semantic tokens, a surface (stage, band, toast) overrides component tokens, and neither touches the button rules themselves.

/* How the yellow band re-skins any button inside it */
.band .btn { --btn-bg: var(--color-bg-stage); --btn-fg: var(--color-fg-on-stage); --btn-border: var(--color-bg-stage); }

In the dark theme the accent stays the same butter yellow, and its label stays ink (8:1 on light, the same pair on dark). The secondary button turns into a charcoal surface with a light --color-border-strong outline. Hover shadows switch from ink to yellow (--color-shadow), so lifted buttons glow like stage lights.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form. A button-styled link (“Book for Sat 14 Nov”, which jumps to the stub) stays an <a href>. Toggle buttons follow the APG Button pattern with aria-pressed. Never use a <div> with a click handler.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
EnterActivates the button (and follows a button-styled link).
SpaceActivates a <button> on key up, so moving away before releasing cancels it. It does not activate links.

Focus

On newsprint the ring is a 3px ink outline with a 3px offset. On the stage and in dark mode it turns yellow. It appears on :focus-visible only, so mouse clicks don’t show it. On a yellow primary button the offset gap shows the page behind, so the ink ring sits 11:1 against the canvas.

Labelling

The visible label is the accessible name. Icon-only buttons have an aria-label that names the object, for example “Share Abigail Mensah’s profile”. A short visible label can be extended with aria-label only if the label text stays at the start of the name (“Pick” becomes “Pick Fri 20 Nov”), which satisfies WCAG 2.5.3 Label in Name. Loading buttons keep their name and add aria-busy. Progress is announced through the page’s role="status" region.

Motion

The lift, shadow and fill change take --duration-fast (90ms). Under prefers-reduced-motion the tokens drop to near zero, so states change instantly. The loading spinner keeps turning on --duration-loop because it is a status indicator, not decoration.

Touch

Medium (44px) and large (56px) meet the comfortable target. Small (36px) still clears the 24px minimum and only appears inside 44px-plus rows. Buttons in a cluster are 8px apart. Nothing depends on hover: the lift is decoration.

Content

  • Start with a verb, in sentence case in the source (CSS adds the uppercase): “Request to book”, “Try again”, “Apply as an artist”. Never “OK”, “Submit” or “Click here”.
  • Name the object or the date when the context is ambiguous: “Book for Sat 14 Nov”, “Search within 120 km · 2 choirs free”. A middle dot (·) separates the action from its detail.
  • Destructive labels name what is lost: “Cancel booking”, not “Confirm”.
  • Keep it to four words or fewer before the dot. The label must fit at 360px.
  • Loading labels use the present tense with an ellipsis: “Checking calendars…”, “Sending request…”.

Drift fixed during extraction:

  • Primary, count badge and band buttons read the primitive --palette-ink for their outline. They now use --color-border-on-accent, or --color-bg-stage on the band.
  • .btn--ink borrowed --color-fg-default and --color-bg-canvas. It now uses the inverse pair.
  • A disabled primary kept its yellow fill. Disabled now drops to the sunken fill for every variant.
  • aria-pressed="true" (“Saved” on the profile) had no visual state. Pressed is now a yellow fill with a filled icon.
  • Ghost hover had no data-state hook, and the top-bar “Saved” button needed an inline style reset. Both are fixed in components.css.
