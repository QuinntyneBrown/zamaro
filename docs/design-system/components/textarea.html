Textarea

A textarea holds a few sentences: the message Naomi sends with a booking request, about her church, the room and the songs she loves. It grows as she writes and counts what is left.

WCAG 2.2 AAStatus: stableNative <textarea>Class .textarea

Overview

Use a textarea when the answer may run past one line: the booking message, a note about parking or sound, a review. For a name or a town use a text field. Always put it in a form field.

  • Default: at least 6rem (about three lines) tall, resizable vertically.
  • Auto-grow (.textarea--autogrow): grows with the text up to 20rem, then scrolls. Use it for the booking message.
  • With counter: when there is a limit, a .field__counter on the label row shows “used / limit”.

Zamaro does not use rich text. Line breaks are kept; links are made clickable when shown to the artist.

Anatomy

  1. LabelStamped overline, with “(optional)” when it is.
  2. Counter“used / limit” in mono tabular figures on the label row.
  3. Text area2px charcoal rule, square, 8px × 12px padding, body text at 1.6 line height. At least 6rem tall.
  4. Resize handleVertical only, so the layout never breaks sideways. Hidden by auto-grow, which sizes itself.
  5. HelpOne line saying what to write. Errors appear above it.

Variants

Default

Three rows, resizable vertically. The placeholder hints at content and is not the label.

Auto-grow with a counter: the booking message

0 / 2,000

Abigail reads this before she accepts. Nothing is charged yet.

Type in it. The box grows with the text (where the browser supports field-sizing), the counter updates, and a polite message is announced once when 20 characters are left.
HTML
<div class="field">
  <div class="field__row">
    <label class="field__label" for="ta-message">Message <span class="field__optional">(optional)</span></label>
    <span class="field__counter" id="ta-message-count" data-counter-for="ta-message" data-limit="2000" data-live="ta-message-live">0 / 2,000</span>
  </div>
  <textarea class="textarea textarea--autogrow" id="ta-message" name="message" maxlength="2000"
            aria-describedby="ta-message-help ta-message-count"
            placeholder="Your church, the room, the songs you love.">We’re hosting a worship night for churches across Burlington, about 250 people. We’d love Goodness of God and Great Is Thy Faithfulness, and our youth band would like to join you for two songs. If it’s easier, call me on 905-555-0123.</textarea>
  <p class="field__help" id="ta-message-help">Abigail reads this before she accepts. Nothing is charged yet.</p>
  <p class="visually-hidden" id="ta-message-live" aria-live="polite"></p>
</div>

maxlength equals the limit (2,000 for the booking message), as in every mock, so the text can never go over; the counter on the label row shows the limit before it is reached. A lower bound (minlength, or a required message) is checked on submit and shown as an error under the box.

Sizes

Textareas have one width (their field) and one starting height; auto-grow handles the rest.

Both themes

  • Invalid is used for a missing required text or one under its minimum length (a review needs 20 characters). Contact details are not an error: L2-046 replaces a phone number or email with “[contact details shared after booking]” for the recipient until the booking is confirmed, and a note under the message tells the sender.
  • Read-only shows a sent message on a booking request: Naomi can select and copy it, not edit it.
  • Disabled is for the moment a request is being sent; the whole form goes busy.

Responsive behaviour

  • Full width of its field at every breakpoint. In the booking stub that is the sidebar width on desktop and the page width on phones.
  • Auto-grow caps at 20rem so the submit button stays reachable on a phone; past that the textarea scrolls inside itself.
  • Browsers without field-sizing keep the 6rem box with a vertical resize handle. Do not add a script for auto-grow; the fallback is fine.
  • 16px text, so phones do not zoom on focus.

Theming

The textarea shares the field component tokens with text fields: --field-bg, --field-fg, --field-border. Its height is not --field-height but a 6rem minimum, and its line height is --line-height-normal. In dark mode it is a charcoal box with a light rule; in the booking stub it stays paper because the stub is a paper island.

Accessibility

Role and pattern

Native <textarea>, a multi-line textbox. There is no APG widget pattern; follow the W3C WAI forms tutorial.

Keyboard

KeyAction
Tab / Shift+TabMoves into and out of the textarea. Tab never inserts a tab character.
EnterInserts a new line. It does not submit the form.
Ctrl/⌘+EnterNot used. Submitting stays on the button so nobody sends by accident.

Focus

The double ring (--shadow-focus) around the whole box. The caret position is kept when focus returns after an error summary link.

Labelling

A visible label with “(optional)” when it is. aria-describedby links the error, then the help, then the counter. The counter is not a live region; a separate visually hidden aria-live="polite" element announces once when 20 characters are left, and once when the text goes over.

Motion

Auto-grow resizes without animation. The rule and ring fade over --duration-fast, instant under reduced motion.

Touch

The box is at least 96px tall and full width. The resize handle is a mouse affordance only; touch users rely on auto-grow.

Content

  • The label names the thing (“Message”), the help says what helps the artist decide: “Your church, the room, the songs you love.”
  • Prefill nothing in the message. A canned greeting reads as spam to artists.
  • Limit by characters (2,000 for the booking message and the message thread, 500 for a reply or a reason, 1,000 for a review, as L2 sets them), set maxlength to that limit and say so with the counter, not with an error after the fact.
  • Errors say what to change: “Write at least 20 characters; you have 8.”
