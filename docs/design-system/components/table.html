Component · Data display

Table

A table lines up booking requests so a coordinator can compare them: who, when, which gathering, what it costs and where it stands.

WCAG 2.2 AAStatus: stableNative <table>Class .table

Overview

Use a table when people compare the same facts across many records: Naomi’s booking requests, an artist’s incoming requests, payouts. Each row is one record and each column is one fact.

  • Use a list when each record is read on its own and has no more than two or three facts, such as saved artists.
  • Use a description list for the facts of a single record, such as one booking summary.
  • Use ticket cards to browse artists. A table is for managing bookings, not for choosing who to book.

Anatomy

  1. Caption<caption> in --text-h4, uppercase, ruled off with a 2px line. It names the table for screen readers.
  2. Column header<th scope="col"> on a sunken fill, mono overline, 2px rule below. Sortable headers hold a .table__sort button.
  3. Row header<th scope="row">: the artist name, bold, so each cell is announced with its row.
  4. Numeric cell.table__num: right-aligned, tabular figures, so dollars line up.
  5. StatusA badge with a tone and a word. Never colour alone.
  6. Wrapper.table-wrap: paper surface, 2px charcoal rule, scrolls sideways on narrow screens.

Variants

All variants share one markup. Add sorting when a list is longer than a screen, selection only when there is a bulk action, and sticky parts only when the table scrolls inside a fixed height.

Sticky header and sticky first column

When a table scrolls inside a fixed height (an admin view, a dialog), .table--sticky pins the header row. When it scrolls sideways on a phone, .table__first on the row headers keeps the artist name in view. Do not combine a sticky first column with a checkbox column: only one column can stick.

Sizes

Default cells are 12 × 16px (--space-3 × --space-4), which leaves room for a 36px small button in each row. .table--dense drops to 8 × 12px for long, read-only tables such as an artist’s payout history. Dense tables hold text and badges only: no buttons, no checkboxes.

Responsive behaviour

  • The table never squeezes its columns below their content. .table-wrap scrolls sideways instead, so the page itself never scrolls horizontally at 360px. This is the one allowed two-dimensional scroll (WCAG 1.4.10 exempts data tables).
  • On phones, put .table__first on the row headers so the artist name stays visible while the other columns scroll past.
  • Header labels do not wrap (white-space: nowrap); keep them to one or two words. Body cells wrap normally, except row actions.
  • Below --layout-breakpoint-md (768px), a table with four columns or fewer can become a list of rows, one record per item. Decide per page and say so in its spec; never hide columns silently.
  • The bulk bar wraps: the count goes first, actions drop below it on narrow screens.

Theming

The table has no component tokens yet: it reads semantic tokens directly. The wrapper is --color-bg-surface with a --color-border-strong rule, the header is --color-bg-surface-sunken, row rules are --color-border-default, hover is --color-bg-subtle and selected is --color-accent-subtle. The bulk bar uses the inverse pair and re-maps its buttons through --btn-bg, --btn-fg and --btn-border, like the toast.

In the dark theme the paper turns charcoal, rules turn into light outlines and the selected tint becomes a deep amber, so the label stays at full contrast. Badges keep their word and tone in both themes.

Accessibility

Role and pattern

A native <table> with a <caption>, <th scope="col"> for column headers and <th scope="row"> for the artist in each row. It follows the APG Table pattern and its sortable table example. It is not a grid: cells are not focusable and arrow keys do nothing special. Sort controls, checkboxes and row actions are ordinary buttons, inputs and links in the Tab order.

Keyboard

KeyAction
Tab / Shift+TabMoves through sort buttons, then each row’s checkbox and action, in reading order.
Enter / SpaceOn a sort button: sorts by that column, or reverses the order if it is already sorted.
SpaceOn a checkbox: selects or clears that row. On the header checkbox: selects or clears every row on the page.
EnterOn a row action: opens the request or runs the action.

Focus

The shared 3px ring appears on the sort button, checkbox box or row button. Rows themselves are never focusable. After sorting, focus stays on the same sort button. After a bulk action, focus moves to the status message or the first remaining row, never to the top of the page.

Labelling

The caption names the table. aria-sort sits on the sorted <th> only, never on the button, and only one column carries it. Each checkbox has an aria-label that names the row (“Select Abigail Mensah, Sat 14 Nov”); the header checkbox is “Select all open requests”. Row actions repeat the visible verb first and add the row (“View request: Abigail Mensah, Sat 14 Nov”) to meet WCAG 2.5.3 Label in Name. An actions column with no visible header gets a visually hidden “Actions”. aria-selected on the row drives the tint; the checked checkbox is what assistive technology announces. The bulk count is a role="status" message.

Row dividers (--color-border-default) are decorative and exempt from 1.4.11: rows are separated by their content and by the hover fill.

Motion

Nothing animates except the skeleton shimmer while loading, which stops under prefers-reduced-motion. Sorting re-orders rows instantly; it never animates rows into place.

Touch

Checkbox boxes are 24px inside a 44px-plus row; small row buttons are 36px with 12px of cell padding above and below. Sort buttons are at least 24px tall and span the header label. Nothing depends on hover.

Content

  • Caption: say whose records and which set, in sentence case: “Naomi’s booking requests”, “Deposits paid”.
  • Headers are one or two nouns: “Artist”, “Date”, “Gathering”, “Fee”, “Status”. Put the unit in the header, not in every cell, when it helps (“Deposit 25%”).
  • Dates as “Sat 14 Nov”; add the year only when the table spans years. Money as “$1,800”, with cents only where cents exist (deposits).
  • Status is one badge word from the fixed set: Requested, Accepted, Deposit due, Declined. See Badge.
  • One row action, a verb: “View”, “Pay deposit”. More than two actions per row belong in a menu.
  • Bulk counts name the thing: “2 requests selected”, not “2 selected”.
