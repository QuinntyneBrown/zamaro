Component · Inputs

Text field

A text field takes one line of typing: the church’s town in the booking bar, an email address, a search, a head count. Square, ruled in charcoal, and always under a visible label.

WCAG 2.2 AAStatus: stableNative <input>Class .input

Overview

Use a text field for short, free-form answers. Always put it in a form field with a label. For longer answers use a textarea; for a fixed list, a select or radio group; for dates, the date picker.

  • Text: “Church location” in the booking bar, the church name in the booking stub.
  • Email: sign-in and the booker’s contact address. type="email" brings the @ keyboard on phones.
  • Search with a leading icon (.input-icon): finding an artist or a song by name.
  • Number: small whole counts only, such as expected attendance.
  • With an addon (.input-group): a unit or currency that belongs to the value, “km” or “$”.
  • Password with a show toggle, on sign-in.

Anatomy

  1. LabelFrom the form field: stamped overline above the control.
  2. Container44px tall (--field-height), square, 2px charcoal rule, surface fill, 12px side padding.
  3. ValueBody text, 16px, so phones do not zoom on focus. Placeholder text, when used, is --color-fg-subtle.
  4. Addon (optional)A sunken box sharing the rule, mono stub type, muted. Holds a unit; linked by aria-describedby.

Variants

Pick the type that matches the data. It sets the phone keyboard, autofill and built-in checks.

File

A native <input type="file"> with .input gets 8px padding and a pointer cursor; the browser’s own button and file name stay, so it works with every assistive technology and on phones (camera and photo library). State the accepted types, size and length limits in the help text, and set accept to match. Files already attached show above the picker as an .upload-list: a dashed, sunken row per file with a success check, the title, a muted line of facts (file name, size, length) and a small ghost “Remove” button named after the file.

Sizes

Medium is the default and matches buttons, so a field and its submit line up. Large suits a single, important field, such as search on its own page. Small is for dense toolbars and table filters on wide screens.

Heights --control-height-sm/md/lg. Small uses 14px text, which makes iPhones zoom on focus, so do not use it on phone layouts.
HTML
<input class="input input--sm" type="text" aria-label="Small example" value="Small · 36px">
<input class="input" type="text" aria-label="Medium example" value="Medium · 44px">
<input class="input input--lg" type="text" aria-label="Large example" value="Large · 56px">

Both themes

  • Hover darkens the rule from charcoal to body ink. Subtle on purpose: fields are not buttons.
  • Focus draws the double ring around the box (--shadow-focus): yellow inside, ink outside on paper; the reverse in dark mode.
  • Invalid (aria-invalid="true") turns the rule red and adds a 2px inner stripe on the left, so it reads without colour. Pair it with a .field__error.
  • Read-only shows a value Naomi can copy but not change, such as her church on a request: sunken fill, dashed rule. It is still focusable.
  • Disabled greys everything and is skipped by Tab. Prefer read-only, or hide the field, when the value still matters.

Responsive behaviour

  • A text field is always 100% of its field. Its width says nothing about the expected length; help text does that if needed.
  • Addons and the show toggle keep their width; the input shrinks (min-width: 0), so groups fit at 360px.
  • Medium and large use 16px text, which stops iOS from zooming on focus. Small (14px) is for wide screens only.
  • In the booking bar the fields stack on phones and pair up from 576px (--layout-breakpoint-sm).
  • .upload-list__text wraps long file names anywhere (overflow-wrap: anywhere), so a 60-character file name never widens a 320px screen; the Remove button stays on the row.

Theming

Inputs, selects and textareas share four component tokens: --field-bg (--color-bg-surface), --field-fg (--color-fg-default), --field-border (--color-border-strong) and --field-height (--control-height-md). States override them: hover sets --field-border to body ink, read-only sets --field-bg to --color-bg-surface-sunken, disabled uses --color-bg-subtle and --color-fg-disabled, invalid uses --color-danger-border.

/* A surface that needs quieter fields overrides the tokens, never the rules */
.toolbar .input { --field-bg: var(--color-bg-surface-sunken); --field-border: var(--color-border-default); }

In dark mode fields are charcoal with a light rule and paper text. The booking bar and stub stay paper in both themes because they carry data-theme="light", the paper island.

Accessibility

Role and pattern

Native <input> with the right type; no ARIA role is needed. There is no APG widget pattern for a textbox; follow the W3C WAI forms tutorial on labels. The show-password toggle follows the APG Button pattern with aria-pressed.

Keyboard

KeyAction
Tab / Shift+TabMoves to and from the field; read-only fields are included, disabled ones skipped.
EnterSubmits the surrounding form.
EscClears a search field.
↑ / ↓Steps a number field by its step.
Enter / Space on “Show”Shows or hides the password. Focus stays on the toggle.

Focus

The double ring (--shadow-focus) replaces the outline and hugs the box, so it is never clipped by a card. Inside an input group the focused input rises above its neighbours (z-index: var(--z-raised)), so the addon does not cover the ring.

Labelling

Every field has a visible <label>; placeholders vanish on typing and fail contrast as labels. Units in an addon are linked by aria-describedby so they are read (“How far can they drive?, 120, km”). The password toggle has aria-controls and keeps the name “Show password” in both states; aria-pressed says whether it is on. Errors: see Form field.

Motion

Rule colour and the focus ring fade in over --duration-fast. Under prefers-reduced-motion they change instantly.

Touch

Medium fields are 44px tall and full width. The whole label is also a target. The show toggle is a 44px button beside the input, not an icon inside it.

Content

  • Labels name the value, not the action: “Church location”, not “Enter your location”.
  • Placeholders, if any, show a real example and end with an ellipsis: “Hosanna Collective, Way Maker…”. Never put rules or the label there.
  • Units go in an addon, not in the value: “120” + “km”, “$” + “1,800”.
  • Prefill what Zamaro already knows (Naomi’s church and town) to save typing (WCAG 3.3.7).
  • Error copy names the fix: “Enter an email address like naomi@riversidecc.ca.”
