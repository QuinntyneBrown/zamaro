Skip link

The first link on every page. It stays out of sight until a keyboard user presses Tab, then appears as a yellow stamp over the top bar and jumps straight to the content.

WCAG 2.2 AA · 2.4.1 Bypass BlocksStatus: stableNative <a href="#main">Class .skip-link

Overview

Every Zamaro page has a skip link as the first element in <body>. Without it, a keyboard user on Discover tabs through the brand, three links, Saved and the account button on every page before reaching the booking bar. With it, one Tab and Enter puts them in <main>.

  • It is visually hidden until focused, then sits 12px from the top-left corner, above the sticky top bar (--z-tooltip).
  • It looks like a primary action: yellow fill, ink outline, uppercase label. That is deliberate: when it shows, it is the most useful thing on screen.
  • .skip-link--static shows it in place for documentation and mocks. Never ship the static form.

Anatomy

  1. Label“Skip to content”: bold 14px uppercase with wide tracking (--text-label), ink on yellow.
  2. StampYellow --color-accent fill, 2px --color-border-on-accent outline, 12 × 16px padding, square corners.
  3. Focus ringThe shared ring, 3px with a 3px offset. Over the top bar it turns yellow, as everything on the stage does.

Click inside the frame’s blank area, then press Tab. The link slides into view over the bar; Enter moves focus to the content.

The skip link has one size; it only appears for a moment and must be easy to read.

Both themes

Skip to content
Skip to content
  • Hidden: positioned above the viewport (top: -10rem), not display: none or visibility: hidden, so it stays focusable.
  • Focus: moves to top: --space-3 and shows the ring. It stays until focus leaves.
  • Hover (while focused): the fill lightens to --color-accent-hover, like the primary button.

Responsive behaviour

  • Same position at every width: 12px from the top and left, over the top bar. It never wraps; “Skip to content” is about 180px wide.
  • Phones with a keyboard (or switch access) get it too; nothing hides it by breakpoint.
  • Because html has scroll-padding-top, landing on #main scrolls the content clear of the sticky bar.

Theming

The skip link reads --color-accent, --color-accent-hover, --color-fg-on-accent and --color-border-on-accent. Those resolve to the same butter yellow and ink in both themes, so it looks identical on newsprint and on the stage theme. It has no component tokens.

Accessibility

Role and pattern

A native same-page link, <a href="#main">, satisfying WCAG 2.4.1 Bypass Blocks. There is no APG widget pattern for it; the page’s landmarks (header, nav, main, footer) are the other bypass mechanism and must also exist. The target <main id="main"> carries tabindex="-1" so browsers move focus, not only scroll, when the link is followed.

Keyboard

KeyAction
Tab (first press on a page)Focuses the skip link and shows it.
EnterMoves focus to <main>; the next Tab reaches the first control in the content.
Tab again (without Enter)Hides it and continues to the top bar as normal.

Focus

The ring is drawn outside the stamp. Over the top bar it is yellow on charcoal; the 3px offset leaves a charcoal gap between the ring and the yellow fill, so the two never merge. The link must be the first focusable element: nothing, not even a cookie banner, comes before it.

Labelling

The visible label is the name: “Skip to content”. A second skip link names its target: “Skip to the booking form”. Do not use “Skip navigation”, which describes what is skipped rather than where you land.

Motion

It appears in place without a transition, so there is nothing to reduce.

Touch

Touch users never see it unless they use a keyboard or switch device. When shown it is 50px tall, above the 44px comfortable target.

Content

  • “Skip to content” on every page. Use the same words everywhere so people learn it (WCAG 3.2.4).
  • A page with one long, important region may add a second link after the first, named for where it lands: “Skip to the booking form” on a profile. Never more than two.
  • Sentence case in the source; CSS uppercases it.

Drift fixed during extraction:

  • The label and outline read the --palette-ink primitive. They now use --color-fg-on-accent and --color-border-on-accent.
  • The mocks’ <main id="main"> had no tabindex="-1", so some browsers scrolled without moving focus. The code above adds it.
  • A data-state="focus" hook was added so the focused look can be documented without a keyboard.
