Progress bar

A ruled track that fills with yellow ink as a long task moves along. Use it when the booker or artist would otherwise wonder whether anything is happening, and how long is left.

WCAG 2.2 AAStatus: stablerole="progressbar"Class .progress

Overview

Use a progress bar for tasks that take more than a few seconds and have a measurable end: an artist uploading a live video, a church working through the four parts of a booking request, an artist profile filling up. Show a percentage when you know it, steps when the task has steps.

  • Determinate (the default) fills to --progress, a percentage set inline.
  • Indeterminate (.progress--indeterminate) slides a block along the track when the end can’t be measured yet, such as “Processing video”.
  • Success and danger recolour the fill when the task ends, so the bar records how it finished.

For waits under about 4 seconds with no measurable end, use a spinner. While content loads into a known layout, use a skeleton. For the three “How booking works” steps on the home page, which are explanation rather than progress, use steps.

Anatomy

  1. Label.progress__head: mono overline, 12px, uppercase. Names the task; the progress bar is labelled by it.
  2. Value.progress__value: percentage or “2 of 4” in tabular figures, so it doesn’t jitter as it counts.
  3. Track.progress__track: 12px tall, paper fill, 2px --color-border-strong rule. Carries role="progressbar".
  4. Fill.progress__bar: yellow (--progress-fill), width from --progress.
  5. Leading edgeA 2px ink rule (--color-border-on-accent) where the fill ends, so the yellow reads against paper.

Meter (completeness gauge)

.meter is a slim 12px gauge for a quantity that is not a running task: how complete an artist’s profile is, or how many of the allowed videos are used. Set the fill with the --value custom property and expose the number with role="progressbar" and aria-valuenow/min/max, named by the visible label beside it. The fill is yellow; .meter--ink fills with ink where yellow would compete with a yellow neighbour (an accent stat). It never animates, and the number is always written next to it.

Add one more video so churches can hear you lead.

Sizes

Progress bars have one size: a 12px track with a 2px rule. Width follows the container.

States

A progress bar moves through a lifecycle rather than pointer states; it is never interactive. Each column below is a real attribute set: aria-valuenow and --progress while measurable, no aria-valuenow while indeterminate, a tone modifier when it ends.

  • Queued: the track shows empty at 0%. Say what it is waiting for if it waits more than a second.
  • In progress: update --progress and aria-valuenow together. The fill eases to each new value over --duration-slow.
  • Working: switch to .progress--indeterminate and remove aria-valuenow when the server takes over and can’t report a percentage.
  • Done: .progress--success at 100%, plus a status message. Remove the bar after a few seconds or replace it with the result.
  • Failed: .progress--danger keeps the fill where it stopped; an inline message or alert says what happened and offers Resume or Try again.

Responsive behaviour

  • The bar takes the full width of its container at every breakpoint; it never has a fixed width.
  • The head is a flex row with the label on the left and the value on the right. A long label wraps; the value stays on the right of the first line.
  • On phones, keep labels to about 30 characters so they fit on one line beside the value: “Uploading ‘Goodness of God’” rather than the full file name.
  • .meter fills its container at every width; its label and number sit above it, never inside it.

Theming

The track reads --color-bg-surface and --color-border-strong. The fill reads the component token --progress-fill (default --color-accent; success --color-success-solid; danger --color-danger-solid) and its width from --progress. The leading edge is --color-border-on-accent, the same ink rule that outlines every yellow fill.

/* Value: set per instance */
<div class="progress__bar" style="--progress: 40%;"></div>
/* Tone: re-map the fill token */
.progress--success .progress__bar { --progress-fill: var(--color-success-solid); }

In the dark theme the track becomes a charcoal surface with a light rule and the yellow fill glows against it. Progress bars don’t sit on the stage or the yellow band; if one must, place it in a paper island (data-theme="light").

Accessibility

Role and pattern

The track has role="progressbar" with aria-valuemin, aria-valuemax and aria-valuenow (WAI-ARIA progressbar role; the APG has no separate widget pattern for it). Indeterminate bars omit aria-valuenow. Use aria-valuetext when a number alone is unclear: “Step 2 of 4: your church”, “40%, about 2 minutes left”. Mark the region being filled with aria-busy="true" until it is done. A native <progress> works too, but can’t carry the ink edge in every browser.

Keyboard

KeyAction
TabNot focusable. Focus stays on the control that started the task, or on Cancel or Resume next to the bar.

Focus

Never move focus to the bar. When the task finishes, keep focus where it is and announce the result; if the bar is replaced by new content, move focus to that content’s heading only when the booker asked for it (pressed Upload).

Labelling

Label the bar with its visible head through aria-labelledby, or with aria-label when there is no visible label. Screen readers don’t announce every value change, and they shouldn’t: put milestones (“Upload complete”, “Upload stopped at 62%”) in a role="status" region.

On light paper the yellow fill alone is too pale to count as a graphic (WCAG 1.4.11), so the ink leading edge and the printed value carry the meaning. In the dark theme it is the other way round: the yellow fill stands out from the charcoal track and the ink edge is decorative.

Motion

The fill eases to each new width over --duration-slow. The indeterminate block slides across the track every 1.4 seconds. Under prefers-reduced-motion the width changes instantly, and the indeterminate bar stops sliding and shows a full, half-opacity fill instead.

Touch

Not a target. Controls beside it (Cancel, Resume upload) follow the button sizes and sit at least 8px away.

Content

  • Label with a present-tense verb and the object: “Uploading ‘Goodness of God’”, “Processing video”, “Sending request to Abigail”.
  • Value: a whole percentage (“40%”), or steps (“2 of 4”). Add time left only when you can estimate it honestly (“about 2 minutes left”).
  • When done, say what is ready: “Uploaded · ready to publish”. When failed, say what is kept: “The first 62% is kept.”
  • Indeterminate labels set expectations: “Processing video · up to 5 min”.
