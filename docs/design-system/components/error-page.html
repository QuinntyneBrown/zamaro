Error page

When a whole page can’t be shown, Zamaro prints a tour poster with the show crossed out: “Show postponed.” Under it, an alert says the booker’s work is safe and offers one way back.

Overview

An error page replaces the main content when the page itself can’t be shown: the link is wrong, the booker isn’t allowed to see it, the server failed, the device is offline, or Zamaro is down for maintenance. It keeps the top bar and footer, so the booker is never stranded.

It is a composition, not a new widget: a poster on the stage (.poster.on-stage) with an .error-poster headline, an optional .strike word and an .error-code reference, followed by an alert in a .page-error container that carries the recovery actions.

  • If only one section failed (the lineup), keep the page and put an alert where the section was, as in the discover error mock.
  • If the page loaded but a list is empty, use an empty state.
  • If a background action failed (saving an artist), use a danger toast.

Anatomy

  1. Stage.poster.on-stage: charcoal in both themes, with the halftone corner. Holds the breadcrumb when there is one.
  2. Kicker.overline.poster__kicker in stage yellow: the error in plain words and its code, “Error 500 · Show postponed”.
  3. Struck word.strike inside the headline: a crossed-out word with a thick line in --color-accent-on-stage (red --color-danger-solid off the stage). Decorative, aria-hidden.
  4. Headline.error-poster: --text-display, 64–160px, uppercase. The page’s <h1>.
  5. Reference.error-code: mono overline in --color-fg-on-stage-muted. The request ID (L2-093, the X-Request-Id header value) support can look up. 500s only.
  6. Recovery alertAn .alert in .container.page-error: what is safe, and one primary action.

Full-page error (.error-page)

The 404, 500 and offline pages put the error straight into the page container with .error-page: a left-aligned column, 24px between parts, with generous top and bottom room. It holds the overline with the status, the .error-poster headline, a lead that says whose fault it is and what is safe, a receipt with the reference (the request ID, L2-093) and time to quote to support, and the recovery buttons, “Try again” first.

Sizes

Three scales, from the whole page down to one section. Use the smallest one that covers what failed.

  • Full page: the compositions above. The .error-poster headline is the page’s h1.
  • Page with known context: when the shell knows where the booker was going (an artist profile), keep the breadcrumb and use the normal .artist-poster__name headline instead of the display headline, as the artist error mock does.
  • Section: only the lineup failed. No poster; an .alert--danger replaces the section’s content and the search stays usable (the discover error mock). See Alert & banner.

The last line of each panel shows .error-poster off the stage, where the strike turns red (--color-danger-solid). Off-stage use is rare: a section-level error inside a dialog, for example. The headline is reduced to --font-size-3xl here only to fit the panel.

Responsive behaviour

  • The headline scales with the viewport (--text-display, 64px at 360px to 160px from about 1070px). Keep each word to six letters or fewer so it never overflows a 360px screen: “On hold”, “No signal”, “Not found”, “Crew only”, “Back soon”.
  • The struck word and the headline wrap onto separate lines on phones; that reads as a poster correction, which is the point.
  • The alert’s actions drop below its text under 576px and fill the width, so “Try again” is the first thing under the thumb.
  • The poster keeps its 48–64px vertical padding; the .page-error container adds 40px above and below the alert.

Theming

The poster reads stage tokens (--color-bg-stage, --color-fg-on-stage, --color-fg-on-stage-muted, --color-accent-on-stage), which are the same in both themes, so an error page always opens on the dark stage. The strike line is --color-accent-on-stage on the stage and --color-danger-solid elsewhere; its thickness is 0.08em, so it scales with the headline. The alert below uses its own --alert-* tokens and follows the theme.

.error-poster .strike { text-decoration: line-through; text-decoration-thickness: 0.08em;
                        text-decoration-color: var(--color-danger-solid); }
.on-stage .error-poster .strike { text-decoration-color: var(--color-accent-on-stage); }

Accessibility

Role and pattern

A normal page with landmarks: the top bar, <main> holding the poster <section> and the alert, the footer. The .error-poster is the <h1>, and the document title names the error: “Page not found · Zamaro”, “Something went wrong · Zamaro”. Serve the real HTTP status (404, 403, 500, 503). The alert needs no live role on a page that loads as an error; give it role="alert" only when it replaces content in a page that was already open (a failed retry, as in the mocks). No APG widget pattern applies; the alert follows the APG Alert pattern.

Keyboard

KeyAction
Tab / Shift+TabSkip link, top bar, breadcrumb (if any), then the alert’s actions, then the footer.
Enter / SpaceActivates Try again, Back to the lineup, or the email link.

Focus

On a full page load, focus starts at the top as usual; the skip link goes to <main>, whose first heading is the error. When an error replaces content in an open page, move focus to the <h1> (with tabindex="-1") so the booker hears what happened. While retrying, focus stays on the busy Try again button.

Labelling

The struck word is a visual joke, so hide it with aria-hidden="true"; the heading then reads “On hold”, “Not found”. The kicker spells out the error in plain words. The reference id is plain text that can be selected, and it is also put into the email link so no one has to copy it.

Motion

Nothing animates on an error page except the busy spinner in Try again, which keeps turning under reduced motion because it reports status.

Touch

Recovery buttons are 44px tall and full width on phones. The email link is a button-styled link of the same size. No action depends on hover.

Content

  • Kicker: the error in plain words, with the code for people who search it: “Error 404 · Wrong venue”, “Error 500 · Show postponed”.
  • Headline: two short poster words, with one struck word in front: “Live On hold”. Keep the joke gentle; churches book these for services and funerals.
  • Sub line: what happened in one sentence, without jargon: “Zamaro hit a problem showing this page.”
  • Alert: what is safe (“Your search is saved and any request you’ve sent is safe.”), whose side it is on (“It’s on our side, not yours.”), and what to do.
  • Actions: “Try again” for failures; a specific destination for 404 (“Back to the lineup”), never just “Home”.
  • Reference: “Reference 7f3c9a2e-41d6-4b8e-9c05-2a6e1d8b4f17 · Fri 9 Oct, 2:32 p.m.”. The whole request ID (L2-093) and the time in L2-110 format; no stack traces.
