Tabs

Tabs show one of several views of the same thing in place: a booker’s requests, upcoming bookings and past bookings. The selected tab gets a yellow underline, or turns solid ink in the stamp style.

Overview

Use tabs when the views are siblings, the person wants one at a time, and switching should not change the URL’s page. Naomi Fraser’s bookings page has three: requests waiting for an artist’s reply, upcoming confirmed bookings, and past ones she can review.

  • Underline is the default: quiet, sits on a 2px rule, the selected tab gets a 4px yellow underline.
  • Stamp (.tabs--stamp) frames each tab and fills the selected one with ink. Use it for a short set (two to four) inside a card or a dashboard panel.
  • Counts (.tabs__count) say how many items each view holds. The selected tab’s count turns yellow.

Do not use tabs to move between pages (use sidebar navigation or top-bar links), to filter a list by style (use chips), or for steps that must be done in order (use steps).

Anatomy

  1. Tab<button role="tab">: bold 14px uppercase label, 44px tall, 16px side padding. Unselected tabs are muted.
  2. Count (optional).tabs__count: mono 12px on a subtle chip; yellow with ink text on the selected tab.
  3. Selected markerA 4px --color-accent underline that sits over the list rule.
  4. Tab listrole="tablist" with a 2px charcoal rule. Scrolls sideways when tabs do not fit; never wraps.
  5. Panelrole="tabpanel", labelled by its tab, 24px below the list. Only one is shown.

Sizes

Medium (44px) is the default and the only size for page-level tabs. Small (.tabs--sm, 36px, 12px labels) is for tabs inside a card or a list row, where 44px tabs would outweigh the content.

Both themes

  • Hover darkens the label to --color-fg-default and fills the tab with --color-bg-subtle. Tabs do not lift.
  • Selected is marked by the yellow underline (or the ink fill in the stamp style), full-strength text and a yellow count, never by colour alone.
  • Focus draws the ring inside the tab (negative offset), so it is not clipped by the scrolling tab list.
  • Disabled greys the label; arrow keys skip the tab. Explain why next to the tabs if it is not obvious.

Responsive behaviour

  • Tabs never wrap onto two rows. When they do not fit, .tabs__list scrolls sideways inside its own box (thin scrollbar), and the page does not.
  • At 360px, “Requests 2 · Upcoming 1 · Past 4” fits in one row. Keep labels to one word so typical sets fit on phones without scrolling.
  • When the selected tab is off-screen on load, scroll it into view (scrollIntoView({ inline: "nearest" })).
  • The stamp style keeps an 8px gap between frames at every width. Panels always take the full width under the list.

Theming

Each tab reads one component token, --tab-fg, which defaults to --color-fg-muted and becomes --color-fg-default on hover and when selected, and --color-fg-disabled when disabled. Everything else is semantic: the list rule is --color-border-strong, the selected underline --color-accent, the hover fill --color-bg-subtle, and the selected stamp --color-bg-inverse with --tab-fg: var(--color-fg-inverse).

In the dark theme the yellow underline stays the same butter yellow and reads even louder on charcoal. The stamp’s inverse fill flips to paper with charcoal text, so the selected stamp is the lightest thing in the row in both themes.

Accessibility

Role and pattern

APG Tabs pattern: role="tablist" with an aria-label, <button role="tab"> with aria-selected and aria-controls, and role="tabpanel" with aria-labelledby. Hidden panels use the hidden attribute.

Activation is automatic for Zamaro’s page tabs. The three booking lists arrive with the page (the counts in the tabs already need them), so showing a panel costs nothing and a keyboard user can preview each list with the arrow keys. Use manual activation when a panel loads on demand, such as the artist’s payouts by period: arrow keys then only move focus, and Enter or Space shows the panel, so moving across three tabs does not fire three requests.

Keyboard

KeyAction
TabMoves into the tab list onto the selected tab, then out to the panel.
← / →Moves to the previous or next tab, wrapping at the ends and skipping disabled tabs. Automatic: also shows its panel.
Home / EndMoves to the first or last tab.
Enter / SpaceManual activation: shows the focused tab’s panel.

Focus

Roving tabindex: only the selected tab has tabindex="0", the others -1. Each panel has tabindex="0" so a keyboard user can reach a panel that has no focusable content. The ring is drawn inside the tab so the scrolling list never clips it.

Labelling

The tab list names the set (“Your bookings”). A tab’s name is its label plus its count (“Requests 2”); add visually hidden words when the number alone is ambiguous. Each panel is labelled by its tab, so screen readers announce “Requests 2, tab panel”.

On newsprint the yellow underline is decoration (yellow on paper is under 3:1); the selected state is also carried by the darker label, the yellow count and aria-selected.

Motion

Nothing animates: the underline and the panel switch instantly. If a panel loads, show a skeleton inside it with aria-busy="true" on the panel.

Touch

Medium tabs are 44px tall and at least 64px wide; small tabs are 36px tall with 12px side padding. Tabs sit 4px apart (8px in the stamp style). The list scrolls with a swipe.

Content

  • One or two words per tab, nouns for what the panel holds: “Requests”, “Upcoming”, “Past”. Sentence case in the source; CSS adds the uppercase.
  • Put the most-used view first and select it by default. For bookers that is “Requests”, because those need action.
  • Counts are plain numbers (“2”, “14”). Show “0” rather than hiding the count, so the tab set keeps its shape.
  • Two to five tabs. More than five is a sign the views should be pages in a sidebar.

Code

// Automatic activation (APG): arrows move focus and select.
tablist.addEventListener('keydown', (e) => {
  const tabs = [...tablist.querySelectorAll('[role="tab"]:not(:disabled)')];
  const i = tabs.indexOf(document.activeElement);
  const next = { ArrowRight: tabs[(i + 1) % tabs.length], ArrowLeft: tabs[(i - 1 + tabs.length) % tabs.length],
                 Home: tabs[0], End: tabs[tabs.length - 1] }[e.key];
  if (!next) return;
  e.preventDefault();
  select(next);        // set aria-selected, tabindex and hidden; manual activation calls next.focus() instead
  next.focus();
});

Sources

  • The booker’s bookings page: “Requests · Upcoming · Past”, reached from “Saved artists (3)” and the account menu in pages/discover/default.
