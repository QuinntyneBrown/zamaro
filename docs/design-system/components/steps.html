Steps

Three numbered panels, like the running order on a set list. On Discover they explain how booking works; in a booking request they show how far it has got.

Overview

Use steps for a short, fixed sequence of three (at most five) stages a booker goes through.

  • Explainer: “How booking works” on Discover. Every step is upcoming; nothing is current.
  • Progress: where a booking request stands (picked, requested, locked in). One step is current (aria-current="step"); earlier steps are complete (data-status="complete").

Steps are not navigation. If a step must be clickable, use tabs or links in a list. For a long or branching flow, use the form layout with sections. For time-based progress use a progress bar.

Anatomy

  1. NumberCSS counter, two digits (“01”), --text-figure-lg on a yellow block with a 2px ink rule.
  2. TitleAn <h3> in --text-h4: a short imperative.
  3. DescriptionOne or two short sentences in body text.
  4. Divider2px charcoal rule between steps: horizontal when stacked, vertical when side by side.
  5. PanelPaper surface inside one 2px frame, 32px padding, number and text 20px apart.

Stepper (multi-step form)

.stepper shows where a person is in a form split over pages, such as the four-step artist application. Each .stepper__step is a numbered stub; the current one is yellow with aria-current="step", completed ones are ink with a check (data-state="done") and link back, and a step with errors after a failed submit takes data-state="invalid" and the danger colour. Say the state in the link’s name too (“About you, done”), because the check is drawn by CSS.

  1. About you
  2. Your music
  3. Price and travel
  4. References and review

Timeline (where a booking stands)

.timeline is the vertical itinerary of one booking or application: numbered stops joined by a dashed line, each with a .timeline__title and a .timeline__meta line with the date, time or deadline (L2-110 formats). Stops that happened take data-state="done" (ink), the stop being waited on takes aria-current="step" (yellow), and a stop that went wrong (cancelled, a failed balance charge) takes data-state="danger". Future stops stay muted.

  3. Confirmed

Sizes

Steps have one size: 32px panel padding and a 40px number. Use the vertical variant, not a smaller size, in narrow places.

States

Steps are not interactive, so there is no hover, focus or disabled state. A step is upcoming, current or complete.

  • Upcoming: yellow number block. In the explainer every step looks like this.
  • Current: aria-current="step" adds a 4px yellow bar along the bottom of the panel. Only one step is current.
  • Complete: data-status="complete" turns the number block ink (the inverse pair).
  • Loading and error do not apply to the explainer, which is static copy. A progress list renders only once the request has loaded; until then its card shows a skeleton.

Responsive behaviour

  • Stacked, full width, under --layout-breakpoint-lg (992px), with horizontal rules between steps.
  • From 992px, three equal columns with vertical rules. Four or five steps also share the row, so keep the copy short.
  • .steps--vertical ignores the breakpoint and always stacks.
  • The number sits to the left of the text at every width; it never moves above it.
  • .stepper stays on one line and scrolls horizontally inside itself on phones (no visible scrollbar); the current step is scrolled into view.
  • .timeline is a single column at every width; long meta lines wrap under their title.

Theming

The panel reads --color-bg-surface and --color-border-strong. The number reads --color-accent, --color-fg-on-accent and --color-border-on-accent, so it stays yellow with ink type in both themes. A complete number reads --color-bg-inverse and --color-fg-inverse: ink on paper in light, paper on charcoal in dark. The current bar reads --color-accent.

No component tokens. Override the semantic tokens on an ancestor to re-skin.

Accessibility

Role and pattern

A native <ol>, so screen readers announce “list, 3 items” and each position. Each step’s title is an <h3> under the section’s <h2>. A progress list carries an aria-label naming what it tracks and aria-current="step" on the current item. There is no APG widget pattern: steps are static content.

Keyboard

KeyAction
TabSkips the steps; nothing in them is focusable. Links inside a description (rare) take focus in reading order.

Focus

No focus style of its own.

Labelling

The CSS number repeats the list position, so it adds nothing for screen readers. data-status="complete" is not exposed to assistive technology, so complete and upcoming steps also say “Done” and “Next” in visible text. aria-current="step" is announced as “current step”; the visible “Now” matches it.

On newsprint the yellow current bar is only about 1.4:1 against paper, so it cannot be the only sign of the current step. The “Now” label and aria-current carry the meaning; the bar is emphasis.

Motion

None. When a request moves to the next step, the page re-renders the list; do not animate the bar sliding across.

Touch

Nothing to tap.

Content

  • Titles: two or three words, imperative, in the booker’s voice: “Pick your date”, “Send a request”, “Lock it in”.
  • Descriptions: one or two short sentences with the reassuring detail: “Nothing is charged yet.”, “pay a 25% deposit”.
  • In progress, replace the generic description with this booking’s facts: the date, the church, the deposit amount.
  • Status words: “Done”, “Now”, “Next”. No ticks or colours alone.
  • Do not number in the copy (“Step 1:”); the list numbers itself.

Drift fixed during extraction:

  • The number used an inline display-font shorthand. It now reads --text-figure-lg.
  • .steps--vertical and data-status="complete" on .steps are still not in the mocks: booking progress uses .timeline and multi-page forms use .stepper.
