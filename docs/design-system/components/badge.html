Badge

A badge is a small rubber stamp that says where something stands: a date is Free or Booked, an application is Submitted or Approved, a payment is Held or Succeeded, an artist is Suspended. Booking statuses are not badges: they use the status stamp.

Overview

Use a badge for a status from a fixed set, shown next to the thing it describes. A badge is not clickable; to filter by status use a chip, and to explain a status use an inline message.

  • Availability: .badge--free (yellow stamp) and .badge--booked (muted, struck through) on tour dates, tickets and saved artists. They mean availability only; a done state such as a verified check uses the success tone.
  • Tones for states outside the booking lifecycle, one tone per meaning: info for waiting on someone (Submitted, Scheduled, Waiting for verification), success for done (Approved, Succeeded, Verified for a Vulnerable Sector Check), warning for needs attention (Held, Paused, “2 reports”), danger for stopped or failed (Suspended, Failed). These are the admin, application and payment states in the mocks.
  • Booking status (Requested, Accepted, Confirmed, Completed, Declined, Withdrawn, Expired, Cancelled) is never a badge: use the status stamp, .stamp--lg in a page head and .stamp--flat in a table or receipt row. A held payment stays a warning badge (“Held”) beside the booking’s stamp.
  • Solid (.badge--solid with a tone) is for the one state in a view that needs action now, such as a Held payment in an admin header. No mock uses it yet.
  • Neutral outline (plain .badge) for labels with no tone: Unavailable (a blocked day or weekday on pages/availability), Off (two-step sign-in not set up, pages/account), This device (the current session), Deposit held and Paid {date} (pages/earnings/default), Not set up (pages/earnings/setup), Not uploaded (the check on pages/edit-profile/empty), “New on Zamaro”. Two-step sign-in that is on is a success badge (On).
  • Count (.badge--count) for a number on a control: the 3 on “Saved”.

Anatomy

  1. DotA 0.5em square in currentColor, like an ink-pad corner. Decorative.
  2. LabelMono overline, 12px, uppercase, wide tracking. The word is the meaning.
  3. Stamp1px rule in --badge-border, 2px square-ish corners, 2 × 8px padding, fill from --badge-bg. Shown here at 16px for legibility.

Sizes

Badges have one size: 12px mono on a 2 × 8px pad. They take the line height of the text they sit in.

States

Badges are not interactive, so they have no hover, focus or disabled state. What changes is the surface under them: rows highlight on hover and selection, and some badges sit on the charcoal stage. Each variant must hold up on all of them.

Responsive behaviour

  • Badges never wrap inside (white-space: nowrap). Keep labels short enough to fit beside a name at 360px; “Free Sat 14 Nov” is the longest in use.
  • In a flex row, a badge keeps its width and the text beside it wraps instead. In the tour dates, the badge moves into the note column on phones rather than squeezing the date.
  • Badges do not scale with the viewport.

Theming

Each variant sets three component tokens: --badge-fg, --badge-bg and --badge-border. The base badge uses currentColor on a transparent fill, so a neutral badge matches whatever text it sits in, on paper or on the stage. Tones map to the status tokens (--color-info-*, --color-success-*, --color-warning-*, --color-danger-*); solid tones use the *-solid fills with --color-fg-inverse or --color-fg-on-danger labels. Free and count use the accent with an ink outline.

In the dark theme the tone fills turn deep and their labels light, solid fills turn light with dark labels, and the yellow Free stamp stays the same yellow with ink text. Booked stays muted and struck through.

Accessibility

Role and pattern

A badge is plain text in a <span>; it has no role and no APG pattern. When a badge changes while the page is open (an application is approved), announce the change through the page’s role="status" region, not by putting a live region on every badge.

Keyboard

KeyAction
TabSkips badges; they are never focusable. A badge inside a button or link is read as part of its name.

Focus

Badges take no focus. Never add tabindex to make one reachable; if it needs an explanation, put the explanation in text next to it.

Labelling

The word is the label: “Booked” is read as “Booked”, and the strike-through is decoration that screen readers ignore. A count badge is only a number, so its meaning goes in visually hidden text (“3 artists”) or in the parent control’s name. Don’t put aria-label on the <span>: a span has no role, so many screen readers ignore the label.

Labels are 12px, so every pair needs 4.5:1. The tone itself is never the only signal (WCAG 1.4.1): each status has its own word.

Motion

Badges do not animate. A status change swaps the badge in place.

Touch

Not a target. A count badge inside a button adds to that button’s target and does not need its own.

Content

  • Use only the fixed set: Free, Booked; Submitted, Scheduled, Waiting for verification; Approved, Succeeded, Verified, On; Held, Paused, report counts (“2 reports”); Failed, Suspended; and the neutral labels Unavailable, Off, This device, Deposit held, Paid {date}, Not uploaded, Not set up and “New on Zamaro”. One to three words, sentence case in the source. Booking statuses go on a status stamp.
  • Add a date only to Free and Paid, and only where the date is not obvious: “Free Sat 14 Nov” on a ticket, plain “Free” in a list of dates, “Paid Tue 16 Jun” on a payout row.
  • Statuses are past participles or states, not actions: “Held”, not “Release payment”. The action is a button next to it.
  • Counts are digits; above 99 show “99+”.

The solid variant is not in the mocks yet. Booking statuses in the mocks are status stamps, not badges.

Drift fixed during extraction:

  • The count badge read the primitive --palette-ink for its outline and was 1.4em minimum. It now uses --color-border-on-accent and is 1.5em, so one digit is a square.
  • Free read --palette-ink for its label. It now uses --color-fg-on-accent.
  • The count’s meaning was an aria-label on a <span> in every mock. Every mock now uses visually hidden text instead (see Do and don’t).
