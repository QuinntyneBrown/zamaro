Marquee

A yellow strip of cities or song titles, set like the bill under a gig poster. It is decoration: it never moves, never holds a link and is hidden from screen readers.

WCAG 2.2 AAStatus: stableDecorative, aria-hidden="true"Class .marquee

Overview

The marquee sits directly under the poster hero and closes the stage with a printed rule. On Discover it lists the cities Zamaro artists drive to; on a full artist profile it lists the songs the artist leads.

  • Use it at most once per page, between the poster and the first section.
  • It only repeats content the page already shows in an accessible form: the cities in the search’s location and radius fields, the songs in the setlist. If that content is not on the page, do not add a marquee.
  • It is not a ticker, a news strip or navigation. For announcements use a banner; for links use the top bar or a list.
  • It is static by design. The text runs off the right edge and is clipped, which already reads as “the bill goes on”. Nothing scrolls on its own.

Anatomy

  1. StripFull width, yellow fill, 2px ink rules top and bottom, 12px vertical padding. Text never wraps.
  2. ItemA <span> per city or song with 20px side padding, set in --text-h4 (22px display, uppercase, 0.08em tracking).
  3. SeparatorA typed “ ✦” at the end of every item except the last. It is part of the item, so it never starts a line.
  4. Clipped edgeoverflow: hidden cuts the strip at the viewport edge. There is no fade and no scroll.

Variants

The default yellow strip follows the poster. Use the stage variant when the strip sits on or between charcoal surfaces, for example above the footer, so it does not add a second yellow band to the page.

Sizes

The marquee has one size: 22px display type with 12px vertical padding, about 50px tall.

States

The marquee is not interactive, so it has no hover, focus, active or disabled state. What varies is whether it appears and how much of it fits.

  • Default: a long list clipped at the right edge.
  • Short list: two or three items leave the rest of the strip empty yellow. That is fine; do not repeat items to fill it.
  • Loading: the city strip on Discover is static content and stays while results load. Never use an empty yellow strip as the placeholder.
  • Empty or new profile: when there is nothing to repeat (an artist with no setlist yet), leave the marquee out instead of showing an empty strip. A new artist with a short setlist keeps the strip: Miriam Haile’s profile shows her four songs.

Responsive behaviour

  • The strip always spans the viewport, edge to edge, outside .container.
  • Text never wraps (white-space: nowrap). On a 360px phone about two cities show; on a 1280px screen about nine. Order the list so the first two items make sense alone.
  • The strip clips with overflow: hidden, so a long list can never cause horizontal page scroll.
  • Type and padding do not change across breakpoints.

Theming

The default strip reads --color-accent for the fill and --color-fg-on-accent and --color-border-on-accent for the type and rules, so it is the same butter yellow with ink type in both themes. .marquee--stage reads --color-bg-stage and --color-accent-on-stage for the type and rules.

There are no component tokens. To re-skin, override those semantic tokens on the strip or an ancestor. Never set a raw colour on .marquee.

Accessibility

Role and pattern

A plain <div> with aria-hidden="true". No APG pattern applies because it is decoration. It must be hidden for three reasons:

  • It repeats content: a screen reader user would hear eleven city names, or five songs twice, before reaching the lineup.
  • Each “✦” would be announced as “four-pointed star”.
  • Part of the list is clipped off-screen, so what is read would not match what is seen.

Because it is hidden, the same information must exist elsewhere in an accessible form: the location and radius fields for cities, the setlist for songs.

Keyboard

KeyAction
Tab / Shift+TabSkips the marquee. It never contains links, buttons or anything else focusable. A focusable element inside aria-hidden would be reachable but unnamed.

Focus

Nothing inside takes focus, so the strip has no focus style.

Labelling

None. Do not add aria-label, role or a heading: the strip should not appear in the accessibility tree at all.

Contrast

Hidden text still has to be readable for sighted users, so the strip meets text contrast.

Motion

None, by design. A scrolling ticker that runs for more than five seconds alongside other content would need a pause control (WCAG 2.2.2), would distract people with attention or vestibular disorders, and would make the clipped list even harder to read. The printed look does not need motion: the clipped edge already says the bill goes on. Do not add a CSS animation or the <marquee> element.

Touch

Nothing to tap. The strip does not intercept pointer or scroll gestures.

Content

  • Cities: the region’s anchor first (Toronto), then the booker’s city and the nearest suburbs, outward. Use the city name only, no province.
  • Songs: the first five songs of the artist’s setlist, in setlist order (L2-012, L2-053), title only, no credits or keys. Keep the song’s own capitalisation in the source (“Great Is Thy Faithfulness”); CSS uppercases it.
  • The eleven quick-pick cities on Discover; up to five songs on a profile (fewer when the setlist is shorter, as on Miriam’s four-song profile). End every item but the last with “ ✦”. No commas, no counts, no prices.
  • Never put information in the marquee that is not elsewhere on the page.
