Skeleton

Blank print blocks in the shape of what is coming: a ticket, a poster, a price. The page keeps its layout while calendars load, so nothing jumps when the lineup arrives.

WCAG 2.2 AAStatus: stablearia-hidden + aria-busyClass .skeleton

Overview

Use skeletons on first load of a view whose layout you know: the lineup on Discover, the artist profile, the booking stub. Build them from the real component (a .ticket, a .stub, the .artist-poster) with skeleton blocks in place of text and images, so the loaded page lands in exactly the same place.

  • Pair every skeleton area with one line of status text, such as “Finding who’s free on Saturday 14 November…”, so the wait is announced and explained.
  • Don’t use skeletons for actions (sending a request, saving); use a busy button or a spinner.
  • Don’t use them for content that refreshes while it is already on screen; keep the old content and show a spinner.
  • If loading fails, replace the skeletons with an alert; if it returns nothing, with an empty state.

Anatomy

  1. Image blockThe ticket’s art area as one .skeleton; it fills the grid cell.
  2. Text line.skeleton--text: 16px tall. Width modifiers vary the line lengths so it reads as copy.
  3. Title block.skeleton--title: 28px tall, the height of an h3 line.
  4. Figure block.skeleton--figure: 40px, for prices and big numbers in the stub.
  5. Target block.skeleton--target: 44px square, in place of the save toggle.

Every block is a flat --color-bg-subtle fill with a soft sweep of --color-bg-subtle-hover moving across it. Corners stay square, like the rest of the poster.

Sizes

Heights come from the shape modifier; widths from the width modifiers. Text and title lines default to 70% and 55% of their container. Override with --short (40%), --medium (60%) or --long (90%) instead of inline widths.

--short · 40%
--medium · 60%
--text default · 70%
--long · 90%
Heights: text 16px, title 28px, figure 40px, control 44px, control-lg 56px, target 44px square, circle 40px, poster 56–128px (follows the viewport like the poster headline).

States

A skeleton is either loading (sweeping) or gone. The surface changes its colours: paper, a card, or the stage. The “Still” column shows what prefers-reduced-motion users see (forced here with an inline animation: none).

Both themes

  • Loading: the region has aria-busy="true"; skeletons sweep once every --duration-deliberate (900ms).
  • Loaded: swap skeletons for content in one step, remove aria-busy, and update the status line (“7 artists free on Sat 14 Nov”). Don’t fade each block separately.
  • Slow: after 10 seconds, keep the skeletons and add a sentence to the status line (“Still checking. Some calendars are slow.”).
  • Failed / empty: replace the skeleton list with an alert or an empty state; keep the controls above it (search, filters) so the booker can change their search.
  • Disabled controls while loading: filter chips above the lineup are disabled (and now styled) until results arrive.

Responsive behaviour

  • Skeletons inherit their layout from the component they sit in: the loading ticket stacks its stub below on phones and moves it to the right from 640px, exactly like a loaded ticket.
  • Widths are percentages of the container, so lines shorten with the screen. Heights are fixed rem values, except --poster, which follows the poster headline (clamp(3.5rem, 12vw, 8rem)).
  • Show as many skeleton items as fit the first screen (two tickets on phones, four on desktop), not the full expected count.

Theming

On paper and cards skeletons read --color-bg-subtle with a --color-bg-subtle-hover sweep. Inside .on-stage they read --color-bg-stage-raised with --color-bg-stage-raised-hover, so a loading poster stays charcoal in both themes. There are no component tokens; the gradient is the whole component.

.on-stage .skeleton { background: linear-gradient(90deg, var(--color-bg-stage-raised) 0 40%,
  var(--color-bg-stage-raised-hover) 50%, var(--color-bg-stage-raised) 60% 100%) 0 0 / 300% 100%; }

In the dark theme the subtle greys darken to sit just above the charcoal surfaces. Skeleton tickets use --ticket-notch-bg for the perforation notches like any ticket, so the notches match the page behind them.

Accessibility

Role and pattern

Skeletons are presentation only: put aria-hidden="true" on the skeleton container (the list, the poster block, the stub). Mark the region that is loading with aria-busy="true", and announce the wait once in a role="status" element outside the hidden part. No APG pattern applies; this follows WCAG 4.1.3 Status Messages.

Keyboard

KeyAction
TabSkips skeletons entirely: they contain no links or buttons. Real controls around them (search, filters) stay reachable; filters may be disabled until results arrive.

Focus

Nothing to focus. When content replaces skeletons, don’t move focus; the status line announces the result. Make sure no focusable element sits inside an aria-hidden skeleton.

Labelling

One status message per loading region: “Finding who’s free on Saturday 14 November…”, “Loading artist profile”. Don’t give each skeleton block a label. Keep the page <h1> a real heading while loading (visually hidden if needed), separate from the status element.

Skeleton blocks are deliberately low contrast and exempt from WCAG 1.4.11: they carry no information and are hidden from assistive tech. The status text carries the meaning.

Motion

The sweep is a slow, low-contrast gradient that moves once every 900ms (--duration-deliberate). Under prefers-reduced-motion the animation is removed and the blocks stay still.

Touch

Not targets. A loading ticket ignores hover and focus-within (.ticket--loading), so it doesn’t lift as if it could be opened.

Content

  • Skeletons have no text. The words live in the status line: a present-tense verb, the date and an ellipsis: “Finding who’s free on Saturday 14 November…”.
  • The loading page keeps everything already known: the search, the date in the poster, the breadcrumb (“Discover · Sat 14 Nov”), section headings like “The lineup”.
  • Mirror the shape of the real copy: a short kicker line, a title line, a meta line. Don’t draw lines where the loaded component has none.
