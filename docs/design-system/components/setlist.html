Setlist

The setlist is the songs an artist leads, printed like the list taped to a stage monitor: a big number, the title, who wrote it and the key.

Overview

Use the setlist on an artist’s profile (“Songs Abigail leads”, L2-016) and in the artist’s own setlist editor. A booking request carries song wishes in its free-text message (L2-028), not as a setlist. It tells a worship coordinator, at a glance, whether the artist knows the songs the congregation sings and in which key.

  • It is a numbered <ol>: the numbers are part of the poster look, but the order is the artist’s own, and the first five songs are the ones the header strip repeats.
  • Use a plain list for anything that is not songs, and a table if songs need more than title, writer and key (length, tempo, who sings lead).

In the frontend the setlist is a zm-* component in the shared components library. The setlist as it sits on the artist profile (as on pages/artist/default) is the “profile setlist” composite, which has its own perf-test scenario (AGENTS.md, Component perf tests).

Anatomy

  1. NumberA CSS counter, two digits (“03”), in the 24px display figure face, muted. Generated, so the source stays a clean list.
  2. Song.setlist__song: 20px condensed display, uppercase, tight leading.
  3. Credit.setlist__credit, inside the song: writer or source in 14px muted sans, sentence case.
  4. Key.setlist__key: mono stub text, never wraps.
  5. RuleHairline under each song, 16px above and below.

Editable

.setlist--edit is the artist’s own setlist in the profile editor: one column, and each song gets .setlist__controls with a key select and icon buttons to move it up or down and remove it. Every control is named after the song (“Move Way Maker up”); the first song’s Up and the last song’s Down are disabled. On phones the controls drop under the song title.

Sizes

The setlist has one size. Use the single-column variant where space is tight.

States

Songs are not interactive, so there is no hover or focus. The setlist has content states.

Loading: a title bar and a short credit bar per song, in the list’s final position.
  • Long titles wrap inside the song column; the number and key stay on the first line.
  • Key unknown or flexible: write “Any key”. Never leave the key column empty, or the row looks broken.
  • Empty: an artist with no songs listed shows a quiet empty state: “{first name} hasn’t listed songs yet. Ask for yours in your message.” No mock shows it yet: every artist in the mocks has at least four songs.

Responsive behaviour

  • Below 768px: one column. Each row is a 48px number column, the song, and the key.
  • From 768px (--layout-breakpoint-md): two columns with a 32px gap. Songs flow across then down (01 02, 03 04), so the numbers still read in order.
  • The key never wraps. At 360px “Key of B♭” still fits beside a two-line title.
  • Inside narrow containers the viewport rule would still split the list, so add .setlist--single there.
  • .setlist--edit: below 768px the controls sit on their own line under the song; from 768px they line up at the end of the row.

Theming

The setlist has no component tokens. Numbers and credits are --color-fg-muted, songs and keys are --color-fg-default, rules are --color-border-default. On the dark stage the paper text turns light on charcoal and the muted numbers stay legible; nothing else changes. Inside the booking stub it follows the stub’s surface in both themes.

Accessibility

Role and pattern

A native <ol> with role="list" (Safari drops list semantics when list-style is none). No APG pattern applies. Label the list with the section heading (aria-labelledby="songs-title") or an aria-label when there is no heading.

Keyboard

KeyAction
TabSkips the setlist; songs are not interactive.
Screen reader list keysAnnounce “list, 8 items” and move song by song.

Focus

No focus. If songs become links (to a chart or a recording), each title becomes the link and gets the shared ring.

Labelling

Each item reads as number, title, credit and key: “03 Great Is Thy Faithfulness Thomas Chisholm, 1923 Key of D”. The two-digit number is CSS-generated and is read by most screen readers. Write keys with the real flat sign (♭) and sharp sign (♯), which screen readers say as “flat” and “sharp”; never “Bb”, which is read as a word.

Content

  • Song titles as published, in title case, because they are names (“Great Is Thy Faithfulness”). CSS uppercases them anyway.
  • Credit the writer, the band that made it known, or the tradition: “Sinach”, “Bethel Music”, “Traditional Ghanaian”. Add a year only for hymns (“Thomas Chisholm, 1923”).
  • Keys as “Key of D”, “Key of B♭”, or “Any key”.
  • A profile lists every song the artist added, up to 50 (L2-053), in the artist’s order; the first five also run in the header strip (L2-012).
  • Medleys say what they are: “Twi praise medley”.
