Iconography

A small set of plain stroke icons, drawn with square caps and mitred joins like cut vinyl. Icons support words; they almost never replace them.

Overview

Zamaro uses few icons. The mocks need seven. Every icon is an inline SVG on a 24-unit grid with a 2.25 stroke, square caps and mitred joins, coloured with currentColor so it follows the text it sits in.

Style

Outline by default. Filled (.icon--fill, or a filled heart inside a pressed toggle) means on. The brand mark is the mic in a yellow square.
  • 24×24 viewBox, 2px safe area, 2.25 stroke, stroke-linecap: square, stroke-linejoin: miter, no fill.
  • Shapes are built from straight lines and simple arcs. No gradients, no two-tone.
  • Typographic ornaments do part of the icon work: ✦ separates marquee items, ★ shows ratings, ✓ marks pressed chips, and · separates details. Each sits in text, so screen readers get words around it.

Sizes

.icon--sm 16px.icon 20px.icon--lg 28px

16px goes inside chips, field messages and the brand mark; 20px inside buttons and nav (the default); 28px leads alerts. Icons are always flex: none so they never squash.

Labelling

  • Decorative icons next to a visible label get aria-hidden="true". This is the default.
  • An icon-only control puts the name on the control (aria-label="Share Abigail Mensah’s profile"), not on the SVG.
  • An icon that carries meaning in a status (warning in an alert) is still hidden, because the alert’s title says it in words.
  • Meaningful icons need at least 3:1 against their background. They inherit text colours, which already pass 4.5:1.
  • In forced-colours mode, currentColor strokes follow system text colours automatically.

Usage

  • One meaning per icon across the product: the heart is always “saved”, never “like” or “favourite worship song”.
  • Leading icons for state or object (Try again, Saved); trailing arrow for “go on”.
  • Don’t add an icon to every button. The mocks use them on fewer than one in three.
