Foundation

Responsive

Most bookers search on a phone between services, so everything starts at 360px. Breakpoints add room; they never add features a phone can’t reach.

Mobile first360 / 576 / 768 / 992 / 1200
  • Overview
  • Component behaviours by breakpoint
  • Touch and pointer
  • Fluid display type
  • Testing matrix

Overview

Base styles target a 360px phone. The breakpoints are the L2 viewport classes: XS below 576px, SM from 576px, MD from 768px, LG from 992px and XL from 1200px. min-width queries at 576, 768, 992 and 1200px (36, 48, 62 and 75rem) add columns and side-by-side layouts. Spacing and body type never scale with the viewport. Only the poster-sized display type is fluid.

Touch and pointer

  • Targets are at least 24px (WCAG 2.5.8). Chips, nav links, the save toggle and medium buttons are 44px.
  • Nothing important is hover-only. Ticket lift and button shadows are decoration; every action is a visible control.
  • Fixed bottom elements (toasts, full-screen dialog footers) add env(safe-area-inset-bottom).
  • Full-height layouts use 100dvh.
  • On touch devices every control is at least 44 × 44px (L2-096): under (pointer: coarse) the compact controls (small buttons, link buttons, small fields and chips, the close button, breadcrumb and sort controls, small tabs) grow to --target-comfortable. Links inside running text are exempt, as WCAG 2.5.8 allows.

Fluid display type

Only --font-size-4xl/5xl/6xl use clamp() with a viewport term, and each has a rem floor and ceiling. Names break anywhere so a long choir name wraps rather than overflowing at 360px.
