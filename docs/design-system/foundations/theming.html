Theming

Two themes from one set of roles: newsprint by day, the stage by night. Themes change semantic tokens only; components never know which theme they are in.

Overview

All colour flows through three tiers. Primitives (--palette-*) are raw values. Semantic tokens (--color-*, --shadow-*) give them meaning per theme. Component tokens (--btn-bg, --chip-bg, --field-border, --ticket-notch-bg) live in components.css and point at semantic tokens.

TierExampleChange it to…
Primitive--palette-signal-500: #f3cc3fRetune the brand yellow everywhere
Semantic--color-accent: var(--palette-signal-500)Change what “accent” means in one theme
Component--btn-bg: var(--color-accent)Re-skin one component or one surface

How themes apply

  • Light is declared on :root, [data-theme="light"]. Dark is declared on [data-theme="dark"] and again inside @media (prefers-color-scheme: dark) for :root:not([data-theme="light"]), so the OS choice applies unless the page forces one. The two dark blocks are kept identical. The contrast checker reads both.
  • Each theme sets color-scheme, so native date pickers, selects and scrollbars follow.
  • Shadows are re-declared in every theme because they embed a themed colour. A custom property resolves where it is declared, so a shadow declared once on :root would keep the light ink inside a dark island.
  • The product stores an explicit choice on <html data-theme>. Without one, it follows the OS.
<html lang="en" data-theme="dark">   <!-- forced stage -->
<html lang="en">                      <!-- follows prefers-color-scheme -->

  • The stage (.on-stage, .topbar, .poster, .footer) reads --color-bg-stage, --color-fg-on-stage, --color-fg-on-stage-muted and --color-accent-on-stage, and re-maps buttons, links, focus rings and skeletons for a dark ground.
  • Paper is any element with data-theme="light". The booking bar uses it so the ticket stays newsprint on the dark stage, with every control inside it styled light.

Adding a theme

  1. Add [data-theme="name"] { … } to tokens.css and override semantic colour tokens only (and the shadows, which embed colour).
  2. Add a row to contrast-pairs.json for any new pairing, then run check_contrast.py tokens/tokens.css. It checks every theme it finds.
  3. Regenerate tokens.json with tokens_to_json.py.
  4. Look at the button, ticket and booking pages with the theme forced (?theme=name on any docs page).

Contrast and forced colours

  • prefers-contrast: more turns hairlines into strong rules and muted and subtle text into the default ink, in every theme.
  • forced-colors: active hands the focus ring to Highlight and rules to CanvasText. Every raised surface already has a 2px rule, so elevation survives without shadows.
  • prefers-reduced-motion is handled in tokens (see Motion).

Consuming tokens.json

tokens/tokens.json is a W3C DTCG export of all 270 tokens, generated from tokens.css. Aliases are kept ("{palette.signal.500}"), and dark-theme overrides are under $extensions. The Angular app can use the CSS directly; native or email templates can generate constants from the JSON.

"color": { "accent": {
  "$type": "color",
  "$value": "{palette.signal.500}",
  "$extensions": { "com.agent-toolkit.themes": { "dark": "{palette.signal.500}" } }
} }
