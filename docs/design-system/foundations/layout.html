Layout

Mobile first, from 360px. Breakpoints add columns, gutters and margins; the container stops at 1216px; the booking stub becomes a sticky column at 1024px.

Overview

Layout tokens change at breakpoints so components don’t need their own media queries. Custom properties can’t be used inside @media, so the queries repeat the values in rem (40rem, 48rem, 64rem) and scale with the reader’s font size.

The mocks use a 20px phone margin rather than 16px, so tickets’ perforation notches clear the screen edge.

Product grids use .grid (the column grid) or .grid--cards (auto-fill, 18rem minimum). Named compositions such as .lineup, .media-grid, .photo-grid, .reviews and .profile-layout are documented on their component pages.

Container, measure, sidebar, top bar

  • .container centres content at --layout-container-max (76rem, 1216px) with --layout-margin padding.
  • Prose stops at --layout-measure (58ch).
  • The artist page’s booking stub column is --layout-sidebar-width (22rem). It is sticky below the top bar from 1024px.
  • The top bar is --layout-topbar-height (68px including its 4px yellow rule). scroll-padding-top uses it so in-page links (“Book for Sat 14 Nov” → the stub) are not hidden under the bar.

Page templates

Error pages keep the shell (top bar, poster, footer) and put the error in the poster, so the booker can always navigate away.

Usage

  • Write mobile styles first and add min-width queries only.
  • Use minmax(0, 1fr) columns so long names can’t widen the grid.
  • Use 100dvh, not 100vh, for full-height layouts.
  • No horizontal page scroll at 320px: only tables and the tab list scroll inside their wrapper.
