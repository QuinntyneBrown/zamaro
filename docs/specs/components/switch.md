## Purpose and scope

A switch turns a setting on or off right away, with no Save button: "Dark
theme" in a settings list, or an artist's "Calendar feed". On is a yellow
track with the ink thumb at the right. The change takes effect the moment the
switch flips; the page saves it and confirms in a short status message.

Use something else when:

- the answer is sent with a form ("I've read the cancellation terms", the
  account page's email preferences saved with "Save changes", L2-065) →
  [checkbox](checkbox.md);
- it filters the lineup → a filter [chip](chip.md);
- it is the top bar's theme toggle, an icon button → `zm-button` with
  `pressed` ([button](button.md));
- it happens once ("Turn on calendar feed", "Send reminder") →
  [button](button.md).

Out of scope:

- Saving the setting, the confirmation message ("Calendar feed on. Your
  private link is ready to copy.") and the error toast. The page owns the
  request, the `role="status"` region and the [toast](toast.md).
- Reverting after a failed save. The page sets `checked` back; the switch
  only reflects it.
- Grouping. A settings list is a `<fieldset class="choice-group">` with a
  `<legend>` that the page writes.

## Usage

No mock uses a switch today. The inventory
(`usage_inventory.py docs/mocks switch`) finds no `.switch` and no
`role="switch"` in any page, dialog or notification. The places a switch could
have gone use other controls on purpose: the account page's email preferences
are checkboxes saved with "Save changes" (L2-065), the top bar's theme toggle
is a pressed icon button (L2-104), and the calendar-feed dialog turns the
feed on with a "Turn on calendar feed" button because turning it on creates a
secret link that the dialog then shows (L2-058). The design system keeps the
switch in the core set for instant settings, and its specimens are the
configurations the API must build:

| Where | Configuration | Slots / content | States seen | Surface |
|---|---|---|---|---|
| Design system, single setting | label at the end (default) | "Dark theme" | on | surface |
| Design system, settings list in a "Preferences" fieldset | `labelPosition="start"`, fills the row, description | "Dark theme" / "Saved on this device and to your account."; "Calendar feed" / "Your confirmed bookings at a private iCalendar link." | on, off; flips with a status message | surface |
| Design system, states matrix | label at the end | "Reminders" | off, on × default, hover, focus, disabled | surface |
| Design system, disabled with a reason | label and description | "Text reminders" / "Add a phone number to get texts" | disabled off | surface |
| Design system, both themes | label at the end | "Dark theme", "Calendar feed" | on, off, hover, focus, disabled | surface, light and dark |

## Anatomy

1. **Row** — `label.switch`: the whole row is the click target. `inline-flex`,
   gap `--space-3`, min-height `--target-min`.
2. **Input** — `input[type="checkbox"][role="switch"]`, visually hidden (1 px,
   opacity 0) but focusable. It carries the state and the name.
3. **Track** — `.switch__track`: a 3 rem × `--target-min` pill with a
   `--border-width-thick` rule. It must follow the input (sibling selectors).
4. **Thumb** — `.switch__track::after`: a 1 rem circle, inset `--space-0-5`.
   Off at the left, on at the right. Generated by CSS, not markup.
5. **Text** — `.switch__text`: a column holding the label and the description.
6. **Label** — `.switch__label`: names the setting. It is the accessible name.
7. **Description (optional)** — `.switch__desc`: body small, muted; what on
   means in practice, or why the switch is disabled. It is the accessible
   description.

Host: `zm-switch` is `display: inline-flex` and renders one `label.switch`.
With `labelPosition="start"` the host is `display: flex` and the row fills it,
label first and track at the end.

## API

### Inputs

| Input | Type | Default | Required | Rule |
|---|---|---|---|---|
| `label` | `string` | — | yes | The setting's name, a statement true when on: "Dark theme". Rendered in `.switch__label`. |
| `description` | `string` | `''` | no | Rendered in `.switch__desc` and linked with `aria-describedby`. Empty: no description element. |
| `checked` | `boolean` (model) | `false` | no | Two-way: `[(checked)]`. Sets the input's `checked`. |
| `disabled` | `boolean` (attribute) | `false` | no | Native `disabled` on the input. Use it only when the setting cannot apply yet, and say why in `description`. |
| `labelPosition` | `'end' \| 'start'` | `'end'` | no | `start` adds `.switch--start`: label first, track at the end of a full-width row (settings lists). |
| `name` | `string` | `''` | no | The input's `name` ("theme-dark"), for e2e and autofill-free identification. Empty: no `name` attribute. |

### Outputs

| Output | Payload | Rule |
|---|---|---|
| `checkedChange` | `boolean`, the new value | Emitted once each time the person flips the switch (pointer, Space, or the label). Never emitted when the consumer sets `checked`. |

### Content slots

None. The label and description are inputs, so the component can link them to
the input by ID (see Accessibility).

Every string arrives as an input from the consumer's catalogue (L2-111):
`label` and `description`.

## Variants and sizes

| Variant | Modifier | Use for |
|---|---|---|
| Label at the end | — | A single setting, the track leading like a checkbox. The default. |
| Label at the start | `.switch--start` | A list of settings: the tracks line up at the right edge of the column. |

One size: a 3 rem × `--target-min` (24 px) track in a row at least
`--target-min` tall, `--target-comfortable` (44 px) under a coarse pointer. The
row's width comes from its text, or from its container with
`labelPosition="start"`.

## States

| State | Trigger | Visual | Assistive technology |
|---|---|---|---|
| Off | `checked = false` | `--switch-bg` `--color-bg-subtle` track, `--color-border-strong` rule, `--color-fg-default` thumb at the left | "Dark theme, switch, off" |
| On | `checked = true` | `--color-accent` track, `--color-border-on-accent` rule, `--color-fg-on-accent` thumb at the right | "switch, on" |
| Hover | `:hover` on the row | Track rule `--color-fg-default` | — |
| Focus | `input:focus-visible` | Two-tone ring around the track: `--focus-ring-width` outline in `--color-focus-ring` at `--focus-ring-offset` over a `--color-focus-ring-offset` gap, following the pill. The row draws no ring. | — |
| Disabled | `disabled` | Track `--color-bg-subtle`, rule and thumb `--color-fg-disabled`, label `--color-fg-disabled`, `cursor: not-allowed`, no hover change | "dimmed" / "unavailable"; skipped by Tab |
| Saving | the page's request is pending | No change: the switch stays usable and shows the new value | The page's status message |
| Save failed | the page sets `checked` back | The thumb returns to its previous side | The page's danger toast "Couldn't save that setting. Try again." |

A switch has no invalid state (any value is valid) and no busy style (design
system). Position, not colour, is the main cue for on and off.

## Markup

Rendered by `zm-switch`, label at the end, on:

```html
<zm-switch>
  <label class="switch">
    <input type="checkbox" role="switch" name="theme-dark" aria-labelledby="zm-switch-1-label" checked>
    <span class="switch__track"></span>
    <span class="switch__text"><span class="switch__label" id="zm-switch-1-label">Dark theme</span></span>
  </label>
</zm-switch>
```

With a description, in a settings list:

```html
<fieldset class="choice-group">
  <legend>Preferences</legend>
  <zm-switch>
    <label class="switch switch--start">
      <input type="checkbox" role="switch" name="calendar-feed" aria-labelledby="zm-switch-2-label" aria-describedby="zm-switch-2-desc">
      <span class="switch__track"></span>
      <span class="switch__text"><span class="switch__label" id="zm-switch-2-label">Calendar feed</span><span class="switch__desc" id="zm-switch-2-desc">Your confirmed bookings at a private iCalendar link.</span></span>
    </label>
  </zm-switch>
</fieldset>
```

Disabled:

```html
<label class="switch">
  <input type="checkbox" role="switch" aria-labelledby="zm-switch-3-label" aria-describedby="zm-switch-3-desc" disabled>
  <span class="switch__track"></span>
  <span class="switch__text"><span class="switch__label" id="zm-switch-3-label">Text reminders</span><span class="switch__desc" id="zm-switch-3-desc">Add a phone number to get texts</span></span>
</label>
```

IDs are generated per instance (`zm-switch-{n}-label`, `zm-switch-{n}-desc`);
their exact form is free to change.

Consumer templates:

```html
<fieldset class="choice-group">
  <legend>{{ 'settings.preferences' | transloco }}</legend>
  <zm-switch labelPosition="start" name="theme-dark" [label]="'settings.darkTheme' | transloco" [description]="'settings.darkThemeHint' | transloco" [checked]="theme.isDark()" (checkedChange)="theme.setDark($event)" />
  <zm-switch labelPosition="start" name="calendar-feed" [label]="'calendar.feed' | transloco" [description]="'calendar.feedHint' | transloco" [(checked)]="feedOn" (checkedChange)="saveFeed($event)" />
</fieldset>
<p role="status" class="text-caption">{{ statusMessage() }}</p>
```

The `.switch*` classes, `role="switch"` and the native `checked` and
`disabled` are a contract: e2e page objects find a switch by role and name
and read its state from `checked`.

## Design

- Row: `inline-flex`, `align-items: flex-start`, gap `--space-3`, min-height
  `--target-min`, `--text-body`, `cursor: pointer`.
- Start variant: `flex-direction: row-reverse` with `justify-content:
  space-between` and full width, so the track sits at the end of the row.
- Text column: `padding-top` `--space-0-5`; description `--text-body-sm`,
  `--color-fg-muted`.
- Track: 3 rem wide, `--target-min` tall, `--border-width-thick` rule,
  `--radius-full`; background transition `--duration-fast`,
  `--ease-standard`.
- Thumb: 1 rem, `--radius-full`, inset `--space-0-5` from either end; it
  slides on `left` over `--duration-base` with `--ease-spring` (a small
  overshoot).
- The track never shrinks (`flex: none`); the text wraps beside it.

Component tokens, declared on `.switch__track`:

| Token | Aliases | Overridden by |
|---|---|---|
| `--switch-bg` | `--color-bg-subtle` | on → `--color-accent`; disabled → `--color-bg-subtle` |
| `--switch-border` | `--color-border-strong` | on → `--color-border-on-accent`; hover → `--color-fg-default`; disabled → `--color-fg-disabled` |
| `--switch-thumb` | `--color-fg-default` | on → `--color-fg-on-accent`; disabled → `--color-fg-disabled` |

position still shows the value. Under forced colours the track rule is
`CanvasText` and the ring `Highlight` (tokens), and the thumb's position keeps
the state visible.

## Responsive behaviour

- No breakpoint changes the switch. The track never shrinks; the label and
  description wrap beside it.
- With `labelPosition="start"` the track stays at the end of the row at every
  width, so a column of switches lines up on a phone.
- Under a coarse pointer the row grows to `--target-comfortable` (44 px) tall;
  the whole row is the target (L2-096).
- At 320 px "Calendar feed" and "Your confirmed bookings at a private
  iCalendar link." wrap in the text column; nothing clips and the page does
  not scroll sideways. At 200 % zoom the row grows taller.
- Keep switches out of table cells and toolbars; they need their label.

## Accessibility

### Role and pattern

A native `<input type="checkbox" role="switch">`, following the
[APG Switch pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/).
Screen readers announce "Dark theme, switch, on" or "off". A group of switches
sits in a `<fieldset>` with a `<legend>`, written by the page.

### Keyboard

| Key | Action |
|---|---|
| <kbd>Tab</kbd> / <kbd>Shift</kbd>+<kbd>Tab</kbd> | Moves to and from the switch. A disabled switch is skipped. |
| <kbd>Space</kbd> | Flips it and emits `checkedChange`. |
| <kbd>Enter</kbd> | Does nothing. The component prevents its default, so it can never submit a surrounding form. |

### Focus

The two-tone ring is drawn around the track (`input:focus-visible +
.switch__track`): a 3 px outline at a 3 px offset over a
`--color-focus-ring-offset` gap, following the pill (D-9). The row itself never shows a ring.
Flipping never moves focus, and a reverted value after a failed save keeps
focus on the switch.

### Labelling

- The accessible name is the label only, through `aria-labelledby`: "Dark
  theme". The description is the accessible description through
  `aria-describedby`, not part of the name.
- The label never changes with the state ("Turn on…" / "Turn off…"); the role
  says on or off.
- A disabled switch's description says why ("Add a phone number to get
  texts").

### Announcements

None from the switch beyond its state. The page announces the result of the
save in a polite `role="status"` message ("Dark theme on.").

### Motion

The thumb slides over `--duration-base` on `--ease-spring`. Under
`prefers-reduced-motion: reduce` the duration tokens drop to near zero and it
jumps.

## Content and internationalisation

- Label the setting as a statement that is true when on, in sentence case:
  "Dark theme", "Calendar feed". No "Enable", "Turn on" or question mark.
- Use the description for the practical detail: where, when or how often
  ("Saved on this device and to your account.").
- The status message the page shows is a few words: "Calendar feed off. The
  old link stops working."
- The switch has no copy of its own: `label` and `description` come from the
  catalogue through the consumer (L2-111). French runs about 30 % longer and
  wraps beside the track.

## Performance

- Change detection: `OnPush`, signal inputs and a `model` for `checked`. The
  IDs are created once in the constructor. No subscriptions and no `effect`.
- Perf-test scenario: `frontend/projects/perf-test/src/scenarios/Switch.ts`
  renders the "Dark theme" setting, on, with the description "Saved on this
  device and to your account.", `labelPosition="start"`. Iterations are tuned
  in `e2e/perf-test/config/scenario-iterations.mjs` to roughly 100–300 ms.
  The `DarkTheme` composite wraps it once the switch reaches a screen.
- Regression rule: a change to its template, inputs, styles or change
  detection runs the perf test against the base branch with
  `--fail-on-regression` before it is pushed.
- Layout stability: flipping moves only the thumb inside the fixed track; the
  row never changes size (L2-086).
- Imports: Angular core only.

## Implementation notes

The component is planned. Build it as:

- Folder `frontend/projects/components/src/lib/switch/`, file `switch.ts`,
  class `Switch`, selector `zm-switch`, exported from `public-api.ts`.
- `checked = model(false)`; the input's `(change)` sets it from
  `event.target.checked`, which emits `checkedChange`.
- A `(keydown.enter)` handler on the input calls `preventDefault()`.
- Instance IDs from a module counter: `zm-switch-{n}-label` and
  `zm-switch-{n}-desc`; `aria-describedby` only when `description` is not
  empty.
- Styles in `switch.scss`, encapsulated: the row, start variant (with
  `justify-content: space-between` and `:host { display: flex }`), track,
  thumb, states, coarse-pointer height, and the track's two-tone focus ring
  (outline plus the `--color-focus-ring-offset` gap as a `box-shadow`). Disabled overrides the
  `--switch-*` tokens, not the checkbox's `--control-*` tokens (D-4).
- No CDK dependency.
- Add the perf-test scenario `Switch.ts` and export it from
  `scenarios/index.ts`.

## Decisions

- **D-1** *No mock uses a switch. Write the CRD anyway?* Yes. The design system specifies the switch in full as part of the core set, every gate input exists, and the L2 rules that govern any control (L2-096, L2-100 to L2-104, L2-111) govern it. The places that might have used one chose other controls for stated reasons (Usage), so the CRD changes none of those screens.
- **D-2** *Should the switch be a form control (`ControlValueAccessor`) for reactive forms?* No. A switch takes effect at once and must never wait for a form's submit (design system do/don't); a form answer is a [checkbox](checkbox.md). `[(checked)]` with `checkedChange` is the whole contract.
- **D-3** *Label and description: inputs or content slots?* Inputs. The input needs `aria-labelledby` and `aria-describedby` pointing at elements the component renders, and both are always plain text.
- **D-4** *The design-system page says the disabled rule sets the checkbox's `--control-*` tokens, which the track does not read. Which is right?* The intended look the page renders: disabled overrides `--switch-bg`, `--switch-border` and `--switch-thumb`. `components.css` already carries that rule; the component builds it.
- **D-5** *Accessible name: the whole label text, or the label alone?* The label alone, through `aria-labelledby`, with the description as `aria-describedby`. A plain wrapping `<label>` would make "Dark theme Saved on this device and to your account." the name; separating them keeps the name short and the detail available. The design-system markup gains a `.switch__label` span for the ID.
- **D-6** *Start variant layout: the design system sets `justify-content: space-between` inline on each row.* The component builds it into `.switch--start` with a full-width host, so no consumer writes inline styles.
- **D-7** *What does the switch show while the page saves?* Nothing extra. The design system has no busy style and keeps the switch usable; the page announces the outcome and reverts on failure. A second flip during a save is a new `checkedChange`; the page decides which request wins.
- **D-8** *What does Enter do?* Nothing, enforced by the component. A native checkbox inside a form can trigger implicit submission on Enter in some browsers, which would contradict the switch's immediate-effect promise.
- **D-9** *The design system draws the switch's focus as a single outline on the track; L2-101 requires a two-tone ring on every focusable element. Which?* The two-tone ring, the same as every other control: the outline plus a `--color-focus-ring-offset` gap. The design system's track rule lacks the gap only because the hidden input, not the track, receives the global `:focus-visible` style; the rendering shows the intended ring, and the design-system page should catch up. The rendering also showed that forcing focus on the row with `data-state` draws the global ring around the whole row, which the product never does; the component draws the ring on the track only.
